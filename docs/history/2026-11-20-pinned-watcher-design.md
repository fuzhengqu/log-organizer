# 启动时置顶仍监控中转目录：设计说明

## 意图

确保“日志归档助手”启动时已置顶，与运行中切换到置顶具有相同语义：置顶期间主窗口保持显示，静默期提示受到抑制，但中转目录继续被监控，新项目仍进入待归档列表。置顶不是暂停监控，也不触发自动归档。

## 当前行为与问题

`TrayApplicationContext.StartWatcher()` 创建并启动 `InboxWatcher`；若设置中 `PanelPinned` 为真，当前实现随即调用 `watcher.Pause()`。`InboxWatcher.Pause()` 关闭 `FileSystemWatcher`，所以启动时置顶会停止变更通知。相反，运行时 `SetPinned(true)` 仅冻结静默期，不暂停 watcher。两条路径因此不一致，且启动时置顶可能漏掉新增项目。

## 范围与约束

- 仅修复启动时置顶与运行时置顶语义不一致的问题。
- 保持置顶期间的文件监控及待归档列表更新。
- 保持置顶期间抑制静默期提示；取消置顶后恢复剩余静默期。
- 不改变明确点击“归档”才移动文件、冲突处理或托盘生命周期等既有行为。
- 不提交或推送变更。

## 考虑的方案

1. **推荐：置顶只冻结静默期，不暂停 watcher。** 删除启动置顶路径中对 watcher 的 `Pause()`；保留 `ResetQuietPeriod()` 机制。改动局部，并直接与现有运行时置顶行为对齐。
2. **置顶时暂停 watcher，取消置顶时再全量扫描。** 可以在之后发现文件，但置顶期间新增项不能及时进入列表，不符合“新中转项目仍进入列表”的要求，因此不采用。

## 验收

- 新增 Core 回归测试：启动 watcher 后冻结静默期；在冻结期间创建文件并重新扫描；断言 watcher 仍在运行、文件已进入待处理列表且静默期内不会产生待提示批次。
- 取消冻结后，剩余静默期结束时该文件可进入待提示批次。
- 使用 MSTest 独立 runner 运行 Core 测试并确认通过；完整 Release x64 解决方案构建通过。
- 真实 WinUI 界面上的置顶交互仍需单独手动/受支持的 UI 自动化验证，本设计不将代码测试冒充为 GUI 验收。
