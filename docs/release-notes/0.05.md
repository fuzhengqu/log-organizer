# 日志归档助手 0.05

常驻 Windows 托盘的归档工具：下载、截图、日志等文件放进**中转目录**，或直接拖入归档窗口；输入**纯 ASCII 数字问题单号**并点击“归档”后，才会移动到目标目录下的单号文件夹中。

本次只修图钉的显示与清理旧代码，归档流程与目录结构不变。

## 下载

| 屏幕架构 | 文件 | 说明 |
| --- | --- | --- |
| 桌面 Intel / AMD 机器 | `LogOrganizer-0.05-win-x64.zip` | x64 已实机验证 |
| Windows on ARM（少数场景） | `LogOrganizer-0.05-win-arm64.zip` | 由 CI 交叉编译，**尚未在 ARM 设备上实机验证** |

也可以直接下载裸 exe：`LogOrganizer-0.05-win-x64.exe` / `-win-arm64.exe`。压缩包里还有微软官方 VC++ 运行库安装包与 `使用说明.txt`。

## 0.05 变更

- **修好图钉图标不随置顶状态转动**：0.04 让图钉能点了，但图标停在垂直高亮态，取消置顶也不回落。查下来是两个毛病叠加：图标旋转原本写在 `CheckStates` 视觉状态的 setter 里，这个 setter 要新建一个 `RotateTransform`，而它从来没被真正实例化过（同一状态里的颜色 setter 是好的，所以一直没暴露）；另外 `Click` 比 `ToggleButton` 翻转 `IsChecked` 更早触发，处理器读到的是旧值，应用的置顶状态与按钮正好相反。现在旋转直接绑定 `IsChecked`，点击处理排到翻转之后，图标和真实状态不再可能不一致。
- **借调归档接口下线**：删掉了“按中转目录整批归档”的旧入口，归档只有一条路径——把你在列表里明确选中的项按路径搬到单号文件夹。“只移动你放进列表的文件”从此是代码结构本身保证的，不是靠调用方自觉。相关测试同步改写为显式列表的等价用例，覆盖不缩水。
- **清理死代码**：删除托盘菜单里早已不用的“窗口是否可见”参数、`ArchiveResult` 上无人读取的失败计数、以及归档进行中用的冗余互斥标志；开设置窗口改用“已在打开中”判断，避免并发打开同一份配置。
- **修好置顶时保存设置会隐藏窗口**：置顶状态下打开设置并保存，监控重启的顺序是“先释放旧的再建新的”，窗口会在空档里被隐藏。现在改成先建新的、再释放旧的，保存设置后窗口照常在。

## 安装与使用

1. 解压压缩包到普通可写目录，例如 `D:\Apps\LogOrganizer`，双击 `LogOrganizer.exe`。
2. 首次启动会创建中转目录 `D:\Downloads\_收件`（可在设置里修改）。
3. 在设置里选择**目标目录**——归档文件夹会创建在它下面。
4. 文件进入中转目录后会立刻出现在列表里，任务栏图标闪一下；输入单号，点击“归档”才移动文件。

不需要安装 .NET 或 Windows App Runtime。已打包的版本需要 **Microsoft Visual C++ 2015-2022 运行库**，缺失时会提示；压缩包内附有官方安装包。程序未签名，SmartScreen 首次运行可能提示“Windows 已保护你的电脑”，选择“更多信息 → 仍要运行”即可。

## 已知限制

- **ARM64 尚未实机验证**：CI 能编译并产出，但 runner 无法启动 ARM 二进制。ARM 设备上如遇问题，可改装 x64 包（Windows on ARM 支持 x64 模拟）。
- 跨卷移动只校验文件数量与大小，不做逐字节哈希。
- 批次逐项执行，不承诺文件系统事务原子性；中途失败时已完成项目留在目标，其余源项目保留并逐项说明。
- 运行企业策略管控目录时可能写不进 `%APPDATA%`，此时配置保存会失败；把 exe 放到普通目录即可，不需要管理员权限。
